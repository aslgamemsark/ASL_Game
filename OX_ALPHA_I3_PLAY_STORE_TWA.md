## 2. Gaps between here and an actual Play Store listing

1. **No Digital Asset Links (`/.well-known/assetlinks.json`) exists** — this is the required
   app↔website trust link so a TWA shows no URL bar. Must be generated by Bubblewrap/PWABuilder at
   packaging time together with the signing key's SHA-256 fingerprint. Not a defect today: there is
   no Android package yet, so there is no fingerprint to link.
2. **No signed APK/AAB or Bubblewrap project** — `twa-manifest.json` / build config doesn't exist in
   the repo. Everything above is the web-side half; the Android-side half (package id, signing,
   store listing assets) is entirely unstarted.
3. **Camera permission UX in a TWA** — WebRTC inside a Trusted Web Activity uses the same permission
   flow, but first-run camera denial inside a store-installed app has no Play-store-style rationale
   dialog. The app's honest denied-card (D3-verified) covers it adequately, but worth testing on a
   real device before submission.

## 3. Verdict

The web side is genuinely TWA-ready: every manifest/icon/SW prerequisite Bubblewrap checks passes
today, verified against production. The remaining work is purely the Android packaging half
(Bubblewrap init → assetlinks.json → signing → listing), which is owner-scope work that cannot be
done from this repo alone. No web-code changes warranted.
