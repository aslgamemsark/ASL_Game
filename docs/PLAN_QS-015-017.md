## QS-015 — Speak the sign name on a pass

**Ship first.** No dependencies, no design questions, improves all 51 signs rather than adding a
surface to maintain.

### Placement decision

Naïve placement is next to `trackFirstSignSuccess` in `handleAttempt` on `LessonPage` and
`PracticePage`. **Reject it** — that covers 2 of the 6 camera surfaces and creates the exact
duplication this codebase has otherwise avoided.

Correct placement: `web/src/hooks/useRecognition.ts`, at the two sites where
`passCallbackRef.current?.(vr)` fires — line ~356 (classifier-gated path) and the corresponding
call in the `else` branch (~line 380, no-classifier path). Both are inside one file. Every one of
the six pages inherits the behaviour for free, and a seventh camera surface added later gets it
without anyone remembering to wire it.

### Steps

1. **New file `web/src/lib/speak.ts`.** Interface comment first, per `.claude/rules/comments.md`.
   ```ts
   /** Speaks a sign's English name aloud on a successful attempt. No-ops silently when the
    *  browser has no speech synthesis or the learner has turned speech off — callers never
    *  branch on availability. Cancels any in-flight utterance first: a learner signing quickly
    *  must hear the sign they just made, not queue behind the previous one. */
   export function speakSign(name: string): void
   ```
   Body: guard `typeof window.speechSynthesis === 'undefined'` → return; read the setting;
   `speechSynthesis.cancel()`; `speechSynthesis.speak(new SpeechSynthesisUtterance(name))`.

   The `cancel()`-before-`speak()` is the one idea worth taking from the teardown source (their
   `Voice._drain()`); without it a fast learner sits through a backlog of stale words.

2. **Setting.** `web/src/stores/useSettingsStore.ts` already has exactly this shape —
   `soundEnabled: boolean` + `toggleSound`. Add `speechEnabled: true` + `toggleSpeech` beside it.
   Do **not** reuse `soundEnabled`: that gates game SFX (`hooks/useSounds.ts`), and a learner who
   silences effects has not asked to silence the word being taught.

3. **Settings UI.** `web/src/pages/SettingsPage.tsx` already imports `Toggle` and renders four of
   them (theme, sound, vibration, training data). Add a fifth in the same block. Label: "Speak the
   sign name" / helper "Says the word out loud when you sign it correctly."

4. **Wire it.** One import in `useRecognition.ts`, one `speakSign(sign.name)` call at each of the
   two pass sites.

5. **Accessibility.** Respect `prefers-reduced-motion`? No — that is a motion preference, not an
   audio one. Do nothing special; the explicit toggle is the control.

### Test

`web/src/lib/tests/speak.test.ts` — stub `window.speechSynthesis`, assert: (a) speaks when
enabled, (b) silent when the setting is off, (c) silent and does not throw when
`speechSynthesis` is undefined, (d) **`cancel()` is called before `speak()`** — that last one is
the behaviour, not the plumbing, and is the case that regresses.

### Estimate
~half a day including the test. 4 files touched, 1 new.

## QS-016 — Sentence mode (sequence of signs → English sentence)

**Do not start until QS-015 has shipped and a design pass has happened.** This is a new product
surface, not a port. The method is recorded in the backlog entry; this section covers only the
decisions our architecture forces that theirs did not.

### Three decisions that differ from the source

1. **The buffer appends verified passes, not guesses.** Their `classify()` cannot return "no
   sign" — any hand in frame yields a word. Ours produces a real `VerifyResult` with per-parameter
   scores. So our buffer subscribes to the same `onPass` we are about to use for QS-015; there is
   no separate classification path to build.

2. **The LLM call is server-side.** Theirs reads `ANTHROPIC_API_KEY` from the environment of a
   desktop script. We have no `supabase/functions/` directory yet — this feature creates the
   first edge function. An API key in the client bundle is not an option.

3. **No hardcoded fallback table.** Theirs reconstructs its demo sentence from almost any subset
   of its six words, which means the LLM path is never load-bearing in the demo video. Our
   fallback is the plain joined gloss (`"HELLO YOU WANT COFFEE"`) shown as-is with a "couldn't
   reach the interpreter" note. Honest degradation over a convincing fake.

### Build order

1. Edge function `supabase/functions/gloss-to-sentence` — takes `{ signs: string[] }`, returns
   `{ sentence: string }`. Model, max_tokens and timeout come from environment config, never
   inline (`.claude/rules/no-hardcoding.md`). Rate-limit per user.
2. `useSignSequence` hook — the gloss buffer (cap 10), fed from `onPass`.
3. The finish gesture. Their version: both hands open, held 2s, progress bar, timer decays at
   `dt*2` on dropout so a momentary detection loss doesn't reset progress, plus a latch so it
   fires once per hold. All three details are worth keeping; the decay and the latch are the
   non-obvious ones.
4. `SentencePage` — buffer as pills, live sentence, speak on finish (reuses QS-015's `speakSign`).

### Open question for the design pass
Is this a **practice mode** (free-form, "sign anything") or a **lesson type** (a target sentence
to reproduce)? These have different content requirements and different success criteria. Answer
this before writing code — it determines whether the edge function even needs to be creative.

### Estimate
Not estimable until the question above is answered. Rough order: several days.

## QS-017 — Activate the dormant NMM parameter

**Do not schedule standalone.** Pick this up together with the first sign that actually requires
a non-manual marker. Turning on a second per-frame MediaPipe model with nothing consuming its
output costs frame budget for zero gain, and the 2026-07-31 pass already fought a 28 Hz loop.

### Current state (verified 2026-08-07)

- `web/src/engine/schema.ts:92` — `NmmReq` defined.
- `web/src/engine/verifier.ts:442` — `scoreNmm` implemented; `:508` wires it into the parameter
  list; `:398` documents that a missing requirement scores 0 and is skipped.
- `web/src/engine/capture.ts:41` — `wantFaceBlendshapes` defaults to **`false`**.
- `web/src/data/signs.ts` — **zero** of 51 signs declare an `nmm` block.

So the engine is complete and the data is empty. Nothing is verified wrongly today; the
parameter simply does not participate.

### Steps, when the triggering sign arrives

1. Pick the sign. Question forms (brow raise, `browInnerUp` / `browOuterUpLeft`) are the clearest
   first case; MUST/SHOULD carry a mouth marker.
2. **Measure before setting a threshold.** `minConfidence` must come from real recorded takes of
   the marker being performed and not performed — not from a guess, and *not* from synthetic
   fixtures. This project has already been burned by exactly that: see the
   `classroom-signs-synthetic-fixtures` finding, where TEACHER/WRITE/READ passed their tests and
   failed live because thresholds were calibrated to ideal synthetic motion. Use `/calibrate`.
3. Enable capture **per sign, never globally** — `wantFaceBlendshapes` should be driven by whether
   the active sign declares an `nmm` block, so learners on signs that don't need it never pay the
   cost. This is the whole reason the flag was made opt-in (`capture.ts:37`).
4. Confusor test, as every sign requires: the correct sign, plus the same manual sign performed
   *without* the marker, which must fail.
5. Measure the frame-rate delta with the second model running before and after. Record it in
   `docs/WORKLOG.md`.

### Estimate
~2 days, on top of whatever the triggering sign costs. Follow `/new-sign`.

## Not doing

- **A structural refactor of `web/src`.** Measured above; the numbers do not support it. A refactor
  with no defect behind it is churn, and `.claude/rules/process.md` is explicit that a minimal
  change preserving a wrong design is worse than nothing — but so is a large change preserving a
  design that was already right.
- **Merging `LessonPage` / `PracticePage`.** They share `useRecognition` already. What is left is
  genuinely different: lessons are ordered with progression, practice is filtered and free-form.
- **Merging the Duel/Room state machines.** Standing decision, unaffected by any of this.
- **Anything from the teardown source's recognition path.** Restated because it is the thing most
  likely to be reached for later: single-frame handshape matching is banned by `CLAUDE.md`, and
  their nearest-neighbour fallback cannot reject any input.
